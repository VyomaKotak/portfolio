01 — Introduction

Before I ever tuned a model, I was the person a global client called when a live system fell over at 2am. You learn a lot about reliability that way.

I spent four years as a systems engineer at Tata Consultancy Services, first keeping enterprise SAP landscapes alive for international clients, then building Python services that cut API response times and gave support teams their week back.

That background is my edge. Most data scientists have never had to explain a production failure to a client. I have. So when I build a model now, I am already thinking about how it gets served, monitored, and kept honest once real traffic hits it.

Today I am completing an MSc in Data Science while building production-grade ML projects and working as a data analyst. The through line has never changed: turn messy reality into something a business can rely on.

Real-Time Fraud Detection Platform

Flagship · Streaming ML
Code ↗

Problem. Fraud is 0.13% of transactions, so a model that cries "all clean" scores 99.87% and is useless. Verdicts are needed in milliseconds, at thousands per second, without freezing out real customers.

Approach. A streaming platform: Kafka → Spark scoring → FastAPI → live dashboard. One shared feature module spans training and serving to kill train/serve skew, and the decision threshold is tunable against a cost matrix. Covered by 26 tests.
